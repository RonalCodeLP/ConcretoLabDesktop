# Refactorización de identificadores con prefijos del equipo

Rama: `refactor/prefijos-integrantes` (creada desde `develop` en el commit `14afd4a`). Sin commits: los cambios quedan pendientes para que el equipo los revise y confirme.

> Los prefijos son una convención de nombres. **No prueban autoría** ni sustituyen el reconocimiento de fuentes externas. Buena parte del código actual se escribió con asistencia de IA (Claude) en las sesiones de las fases 0 a 6; declárenlo según las reglas de su institución.

## Método

- Renombrado **semántico** con el compilador de Java (árboles y símbolos de `javac`): cada uso se resolvió al elemento declarado, así que solo cambiaron sus referencias reales (no cadenas, ni homónimos de otras clases). Incluye pruebas, referencias `Clase::metodo` y enlaces `{@link #metodo}` del Javadoc.
- Un solo prefijo por clase (las clases anidadas usan el de su clase principal).
- Métodos y campos: `prefijo + Nombre` (camelCase). Constantes: `PREFIJO_NOMBRE` (MAYÚSCULAS_CON_GUIONES).
- Los identificadores que ya tenían el prefijo correcto se mantuvieron. Los prefijos antiguos mal escritos se corrigieron: `miajeldDelgado…` → `erickDelgado…` y `WalterQuispeSayhuan…` → `WalterQuispesayhua…`.
- Tres clases cambiaron de nombre (y de archivo): `MiajeldDelgadoVisor3D` → `ErickDelgadoVisor3D`, `MiajeldDelgadoImportacionDxf` → `ErickDelgadoImportacionDxf`, `WalterQuispeSayhuanSismoController` → `WalterQuispesayhuaSismoController` (también en `sismo-view.fxml`).
